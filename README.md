# AI Mystery Room

An interactive detective investigation studio. Write a fictional premise, review the case file that Gemini builds, connect the evidence, and make a suspect accusation.

The web app is React and Vite. The API is Express, MongoDB, and Mongoose. Gemini generation runs on the server. Each case stores its answer privately; public case responses omit the solution until a successful accusation or the attempt limit is reached.

## Requirements

- Node.js 20 or newer
- MongoDB (local or hosted)
- A Google Gemini API key for generating cases

## Run locally

1. Copy `server/.env.example` to `server/.env` and set `MONGODB_URI`, `SESSION_SECRET`, and `GEMINI_API_KEY`.
2. Copy `client/.env.example` to `client/.env` if the API is not running at `http://localhost:5000/api/v1`.
3. Install dependencies from the project root and each app, then start both:

   ```sh
   npm install
   npm --prefix server install
   npm --prefix client install
   npm run dev
   ```

   The web app runs at `http://localhost:5173`; the API runs at `http://localhost:5000`.

Set `CLIENT_URL` to the web app origin when it differs from the default. The server exits with a clear message if `MONGODB_URI` or `SESSION_SECRET` is missing. Case generation reports a configuration error if `GEMINI_API_KEY` is missing. `GEMINI_MODEL` defaults to `gemini-3.8-flash`. Never put server credentials in a `VITE_` variable or commit `.env` files.

On Windows, this workspace sets the integrated terminal's default shell to Command Prompt, where `npm run dev` works without changing PowerShell's execution policy. Open a new integrated terminal after opening the project for the setting to take effect. In development, the API accepts localhost and private LAN origins, and the frontend follows the hostname used to open Vite; this supports Vite's alternate port when a previous frontend is still running.

## API outline

- `GET /api/v1/health` — API health
- `POST /api/v1/auth/register`, `POST /api/v1/auth/login`, `GET /api/v1/auth/me` — account access
- `GET /api/v1/cases`, `POST /api/v1/cases`, `GET /api/v1/cases/:id` — private case files
- `PATCH /api/v1/cases/:id/progress` — reviewed and saved exhibits, notebook notes
- `POST /api/v1/cases/:id/accuse` — deterministic accusation evaluation, up to three attempts

Protected endpoints use a bearer token. All case operations are scoped to the authenticated owner. Generated cases are checked for suspect counts, unique IDs, solution membership, and evidence references before storage.

## Current media behavior

Conversation and document exhibits render as case file UI. CCTV and photo exhibits are clearly marked simulations or image references; Gemini text generation does not create photographs or video. No external media generator is configured.

## Product specification

`spec.md` is the product source of truth. This foundation implements the core create, investigate, take notes, and accuse loop. The deployment setup below covers a first Render and Atlas launch. Automated test suites, richer evidence validation and repair, accessibility review, and optional media generation remain follow-up work before broader production use.

## Deploy to Render and MongoDB Atlas

This repository is configured as one Render web service: Render builds the Vite client, then Express serves the client and `/api/v1` from the same URL. This avoids cross-origin API configuration in production.

### 1. Prepare your database and Gemini key

1. Create a MongoDB Atlas cluster and a database user. Keep the generated MongoDB connection string; replace its username, password, and database name as needed. URL-encode special characters in the password.
2. Create a Gemini API key in Google AI Studio. Keep it private.
3. Do not commit `server/.env`, `client/.env`, or paste their contents into a public issue. Set production secrets in Render only.

### 2. Push the project to GitHub

Create a GitHub repository, then commit and push this project, including `render.yaml`. Confirm `.env` files are not staged:

```sh
git status --short
```

### 3. Create the Render service

1. In Render, choose **New > Blueprint** and connect the GitHub repository.
2. Render reads `render.yaml`. When prompted, set `MONGODB_URI` to the Atlas connection string and `GEMINI_API_KEY` to your key. `SESSION_SECRET` is generated by Render. Keep `NODE_ENV=production` and the configured `GEMINI_MODEL`.
3. Create the service. The first deploy can start before the database allows its outbound connection; the server retries the database connection every 10 seconds.

### 4. Allow the Render service to reach Atlas

1. Open the new Render service and use **Connect > Outbound** to copy its outbound IP ranges.
2. In MongoDB Atlas, open **Security > Network Access > IP Access List** and add those Render CIDR ranges. Avoid `0.0.0.0/0` for a deployed database. If you use Render dedicated outbound IPs, allowlist those addresses instead.
3. Wait for Render logs to report `MongoDB connected.` The app's `/api/v1/health` endpoint should then return `{"status":"ok","database":"connected"}`.

### 5. Open and verify the app

Open the `onrender.com` URL shown in the Render service dashboard. The landing page and API share that origin. Create an account, sign in, and generate a case to confirm MongoDB and Gemini are configured. If the page loads but account actions fail, check Render logs for a MongoDB network or credential error. If only case generation fails, confirm `GEMINI_API_KEY` and `GEMINI_MODEL` in Render's Environment settings and redeploy.

### 6. Make updates

Render can redeploy from the connected Git branch after each push. For a production app, use a paid Render plan to avoid free-instance sleep and cold starts. Free web services spin down after 15 minutes without traffic and may take about a minute to wake.

More detail: [Render Node/Express deployment](https://render.com/docs/deploy-node-express-app), [Render Blueprints](https://render.com/docs/blueprint-spec), [Render outbound IP addresses](https://render.com/docs/outbound-ip-addresses), [MongoDB Atlas IP access list](https://www.mongodb.com/docs/atlas/security/add-ip-address-to-list/).
